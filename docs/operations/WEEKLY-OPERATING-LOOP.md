# Weekly operating loop
Timezone: `America/Bogota`; API timestamps: ISO 8601 UTC.

| When | Max | Action | Output/gate |
|---|---:|---|---|
| Daily 08:00/12:00/16:00/20:00 | automated | Refresh verified allowlist; dedupe by video ID | Signals + Run Log; no publication |
| Monday 08:30 | 20m | Curate new signals, pillar, relevance | Shortlist ≤5; Daniel |
| Monday 09:00 | 25m | Attach sanitized real-work evidence | Grounded candidates; privacy check |
| Tuesday 08:30 | 30m | Select one mission and complete brief | One DRAFT; Daniel chooses |
| Tuesday 17:00 | 15m | Originality/privacy review | APPROVED_FOR_RECORDING or revision |
| Recording | ≤120m | Record from evidence/demo | Raw recording |
| Edit/package | ≤60m extra | Essential edit + derivatives | Upload-ready; approval required |
| Friday | 15m | Log production minutes/native outcomes | Feedback row |
| Fourth Friday | 30m | Review pillar mix, recurring viewers, retention, workload | Monthly decision note |

**Purpose:** recurring-viewer learning per extra production hour. **Acts when:** a verified signal joins sanitized evidence. **Self-check:** allowlisted, fresh, original, safe, backlog current. **State:** video ID + run ID + last checked time. **Bail-out:** partial API data, missing evidence, stale backlog, privacy doubt, rejected approval.

Weeks 1–3: edited long-form + two Shorts + community post. Week 4: live replaces edited long-form + two Shorts + community post. Pillar shares are monthly portfolio targets, not forced weekly slots.
